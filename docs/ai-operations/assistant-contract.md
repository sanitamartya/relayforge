# AI Operations Assistant

## Goal

Provide a read-only, tenant-scoped assistant that summarizes the operational status of webhook deliveries.

## Endpoints

- `GET /tenants/:id/ai/operations-summary`
- `POST /tenants/:id/ai/ask` with a required question of at most 500 characters

The existing tenant bearer-key middleware protects the route. Operational data is queried using the authenticated tenant ID, not a tenant identifier supplied to the model.

## Supported information

- Total webhook deliveries
- Delivery counts grouped by status
- Recent delivery records with a failure or recorded error
- Attempt counts and HTTP response status codes
- Sanitized failure reason excerpts

## Security and reliability requirements

- Use the authenticated tenant context.
- Never trust a tenant ID generated by the language model.
- Never allow arbitrary SQL or database access from the model.
- Retrieve operational facts through controlled backend queries.
- Do not expose another tenant's data.
- Redact credentials and webhook URLs before including failure excerpts.
- Do not invent missing metrics, errors, or delivery statuses.
- Return deterministic facts even when the local model is unavailable.

## Initial restrictions

The assistant is read-only. It must not retry deliveries, create or modify webhook endpoints, change tenant configuration, or execute arbitrary tools or commands.

## Model integration

- Provider interface: `generate(prompt)`
- Initial provider: local Ollama
- Default model: `qwen2.5:3b`
- Default local endpoint: `http://127.0.0.1:11434`
- No paid model API is required.
- Model output is a narrative; returned database facts remain authoritative.

## Observability

Model generation success and unavailability are recorded in `relayforge_background_operations_total` with component `ai-assistant` and operation `generate_narrative`. Prompts and model responses are not logged.

## Success criteria

A tenant can request an operations summary or ask a bounded natural-language question and receive accurate, tenant-scoped facts with an optional local-model explanation. Model errors degrade to deterministic output without exposing provider error details.
